# Snake Battle — MANUAL

> ภาษา: **ไทย** · [English](MANUAL.en.md) · [日本語](MANUAL.ja.md)

เกมงูบนเครื่องเดียว เขียนด้วย `turtle` ล้วน (ไม่ใช้ pygame ในการวาด) มี 2 โหมด:
**1 Player** และ **2 Player Battle** เลือกตัวละครและ power ก่อนเริ่มแมตช์

จุดเริ่มคือ **`main.py`** เท่านั้น

---

## 1. ติดตั้ง & รัน

**ต้องมี**

- Python 3.8+ ที่มี `tkinter` (turtle ใช้ tkinter ข้างใน)
  - Windows / macOS: installer ของ python.org มีมาให้แล้ว
  - Ubuntu / Debian: `sudo apt install python3-tk`
- **ไม่ต้องลงอะไรเพิ่มเลย** — เกมใช้ `turtle` + standard library เท่านั้น
  รูป `assets/*.gif` มาพร้อม repo แล้ว
- ของเสริม (ไม่จำเป็น)
  - `pip install pillow` — เฉพาะตอนจะ generate รูปใหม่ด้วย `make_sprites.py` (เช่นเพิ่มตัวละคร)

> **ไม่ต้องใช้ pygame** ทั้งภาพและเสียงทำงานบน turtle + stdlib ได้ครบ (เรื่องเสียงดูข้อ 6)

**รัน**

```bash
python main.py            # เล่นเกม
python make_sprites.py    # gen รูป GIF ใหม่ทั้งชุด (ต้องมี Pillow)
```

ตอนเปิดเกมจะพิมพ์สถานะเสียง 1 บรรทัด เช่น `SOUND: 8 events via winsound`
หรือบอกว่าทำไมยังไม่มีเสียงและต้องทำอะไร

ฟอนต์และไอคอนหน้าต่างเปลี่ยนได้ที่ `config.py` — ดูข้อ 9.4 และ 9.5

## 3. ปุ่ม

**เมนูหลัก** — คลิกปุ่ม หรือกด `1` / `2`

**หน้าเลือกตัวละคร** — การ์ดใหญ่ 1 ใบต่อผู้เล่น มีลูกศร **◀ ▶** ข้างบนสำหรับพลิกดูตัวละคร
(คลิกที่ตัวการ์ดก็พลิกไปข้างหน้าได้) ไอคอน power คลิกได้ทั้งกล่อง จุดใต้การ์ดบอกว่าอยู่ตัวที่เท่าไหร่
หรือใช้คีย์บอร์ด

| | เลือกตัวละคร | เลือก power |
|---|---|---|
| P1 | `A` / `D` | `W` / `S` |
| P2 | `←` / `→` | `↑` / `↓` |

`Enter` เริ่มเกม · `Esc` กลับเมนู

**ในเกม**

| | 1 Player | 2 Player |
|---|---|---|
| เดิน | ลูกศร | P1 `W A S D` · P2 ลูกศร |
| ใช้ power | `SPACE` | P1 `Q` (หรือ `E`) · P2 `O` (หรือ `P`) |
| เปิด/ปิดเสียง | `X` | `X` |
| เริ่มใหม่ | `R` (ตอนตาย) | `R` (หน้า ROUND OVER = **รอบต่อไป** เก็บสกอร์รอบ + ตาราง MVP ไว้) |
| กลับเมนู | `M` | `M` |

> **power ใช้ปุ่มเดียวต่อผู้เล่น** ไม่ว่าจะเลือก power อะไร เพราะแต่ละคนเลือกได้ 1 อย่าง
> ระบบจึงเพิ่ม power ได้เรื่อยๆ โดยไม่ต้องหาปุ่มใหม่

## 4. ตัวละคร (4 ตัว)

| ตัว | สี |
|---|---|
| AQUA | ฟ้า |
| EMBER | ส้ม |
| VENOM | เขียว |
| ROYAL | ม่วง |

**ทุกตัวเล่นเหมือนกันเป๊ะ** ต่างแค่สี — ไม่มีตัวไหนแข็งหรือเร็วกว่า ตัวละครคือ skin
และในโหมด 2P คือวิธีแยกว่างูตัวไหนของใคร ด้วยเหตุนี้ **สองคนเลือกตัวเดียวกันไม่ได้** —
ลูกศรจะข้ามตัวที่อีกฝ่ายถืออยู่ให้อัตโนมัติ (แต่ power เลือกซ้ำกันได้)

**เพิ่มตัวละคร** — เพิ่ม entry ใน `config.py` (Section 3F) แล้วรัน `python make_sprites.py`
หน้าเลือกตัวอ่านจำนวนจาก registry เอง (จุดบอกตำแหน่งเพิ่มตาม) ไม่ต้องแก้โค้ด UI

อยากอัพรูป `.gif` เองแทนการ gen — ดูข้อ 9

> รูป portrait บนการ์ดวาดด้วย turtle ล้วน (compound shape ย้อมสีตามตัวละคร) ไม่ได้ gen ไฟล์รูป
> และใช้ `.gif` ของ sprite แทนไม่ได้ เพราะ **turtle ย่อขยาย image shape ไม่ได้** —
> หัวขนาด 20x20 ก็จะอยู่ 20x20 ตลอดไม่ว่าจะสั่ง `shapesize()` เท่าไหร่

## 5. Power (5 อย่าง)

| Power | ผล | ค่าใช้ | ระยะเวลา |
|---|---|---|---|
| **SPEED** | เร็วขึ้น 2 เท่า | 50 | 180 เฟรม |
| **STEALTH** | ลำตัวหาย หัวเป็นเงา (**ยังชนได้ทุกอย่าง**) | 50 | 180 เฟรม |
| **SHIELD** | ไม่รับดาเมจเลย | 50 | 150 เฟรม |
| **PHASE** | ทะลุกล่องและหางตัวเองได้ | 50 | 150 เฟรม |
| **FEAST** | ผลไม้ได้คะแนน 2 เท่า | 40 | 240 เฟรม |

หลอด power เต็มที่ 100 กินผลไม้ได้ +25 (2P) / +20 (1P) · กด power ซ้ำระหว่างที่ยังทำงานไม่ได้

**เพิ่ม power** — `config.py` (Section 3G) เขียน effect เป็น "ชนิดของผล" ที่เกมรู้จักอยู่แล้ว:

```python
speed_mult   float   คูณความเร็วหัว
score_mult   float   คูณคะแนนผลไม้
cloak        bool    ซ่อนลำตัว สลับหัวเป็นเงา
invincible   bool    ไม่รับดาเมจ
noclip       bool    กล่องและลำตัวตัวเองไม่ทำอันตราย
```

> `cloak` ซ่อนลำตัวอย่างเดียว **ไม่ได้ทำให้ทะลุอะไร** — มีแต่ `noclip` (PHASE) กับ
> `invincible` (SHIELD) ที่ยกเว้นการชน เดิม 1P ยกเว้น `cloak` ให้ด้วยแต่ 2P ไม่ยกเว้น
> ทำให้ STEALTH กลายเป็น PHASE ที่ดีกว่าในโหมด 1P — แก้ให้ตรงกันแล้ว

ถ้า power ใหม่ใช้ชนิดที่มีอยู่แล้ว → **เพิ่ม entry กับไอคอน จบ ไม่ต้องแก้โค้ดเกมเลย**
ถ้าต้องการผลแบบใหม่ → เพิ่ม key ตรงนี้ แล้วอ่านค่าด้วย `powers_flag()` / `powers_effect()` ใน `entity.py`
ที่จุดเดียวที่ควรสนใจผลนั้น ไม่มีที่ไหนในเกม hardcode ชื่อ power

| 4 | `sound_effect/<ชื่อไฟล์แพ็ค>.mp3` | ใช้ได้เฉพาะเมื่อมี pygame · **ไม่มี pygame = ถูกข้าม** |

**`.wav` มาก่อน `.mp3` ทุกโฟลเดอร์** เพราะ `.wav` เล่นได้ด้วย standard library เพียวๆ

โฟลเดอร์ที่ค้นเพิ่มตั้งได้ที่ `config.py`:

> **ทำไมต้อง `.wav`** — บน Windows เล่นผ่าน `winsound` ที่อยู่ใน standard library
> ไม่ต้องลงอะไรเลย ส่วน `.mp3` **เล่นไม่ได้** ด้วย `winsound` หรือ CLI player
> มีแต่ pygame ที่อ่าน mp3 ได้ และ pygame เป็นของเสริมล้วนๆ
>
> แปลงทั้งโฟลเดอร์ทีเดียว (คำสั่งนี้เขียนไฟล์ `.wav` ไว้ข้างๆ `.mp3` เดิม เกมเจอเอง):
>
> ```bash
> cd sound_effect
> for f in *.mp3; do ffmpeg -i "$f" -c:a pcm_s16le -ac 1 -ar 22050 "${f%.mp3}.wav"; done
> ```
>
> PowerShell:
> ```powershell
> cd sound_effect
> Get-ChildItem *.mp3 | ForEach-Object {
>   ffmpeg -i $_.Name -c:a pcm_s16le -ac 1 -ar 22050 ($_.BaseName + ".wav") }
> ```
>
> **`-c:a pcm_s16le` สำคัญมาก** — ถ้าไม่ใส่จะได้ 32-bit float ที่ `winsound` เล่นไม่ได้

### เจอไฟล์แล้วแต่ไม่มีเสียง — แก้ตรงนี้

**สาเหตุที่พบบ่อยที่สุด: ไฟล์ไม่ใช่ PCM 16-bit** `winsound` เล่นได้แค่ WAV แบบ PCM
8 หรือ 16 bit เท่านั้น ตัวแปลงออนไลน์และ Audacity มักส่งออกเป็น **32-bit float**
ซึ่งนามสกุลเป็น `.wav` แต่ `winsound` เล่นไม่ได้

เกมตรวจให้อัตโนมัติแล้ว เปิดเกมจะเห็นบรรทัดแบบนี้:

```
SOUND: 2 events via winsound  (4 file(s) skipped as unplayable - see sfx.diagnose())
```

แล้วมันจะพิมพ์ตารางบอกทีละไฟล์:

```
event    status     file / reason
eat      ready      eat.wav  [1 ch, 16-bit, 22050 Hz]
bump     UNUSABLE   bump.wav  <-- not a playable PCM wav: unknown extended format...
power    UNUSABLE   power.wav <-- not a playable PCM wav: unknown format: 2
win      UNUSABLE   win.wav   <-- not a playable PCM wav: file does not start with RIFF id
lose     UNUSABLE   lose.wav  <-- 1 ch, 24-bit - winsound needs 8 or 16-bit, not 24
```

| ข้อความ | หมายถึง | แก้โดย |
|---|---|---|
| `unknown extended format` | เป็น 32-bit float | แปลงใหม่เป็น 16-bit PCM |
| `unknown format: 2` | เป็น ADPCM (บีบอัด) | แปลงใหม่เป็น 16-bit PCM |
| `does not start with RIFF id` | เป็น mp3 ที่เปลี่ยนนามสกุลเป็น `.wav` | แปลงจริงๆ ไม่ใช่เปลี่ยนชื่อ |
| `winsound needs 8 or 16-bit, not 24` | เป็น 24-bit | แปลงใหม่เป็น 16-bit PCM |

**วิธีแปลงให้ถูก**

```bash
ffmpeg -i broken.wav -c:a pcm_s16le -ac 1 -ar 22050 fixed.wav
```

**ใน Audacity** — File > Export > Export as WAV แล้วเลือก
**"WAV (Microsoft) signed 16-bit PCM"** ห้ามเลือก 32-bit float

**อยากดูรายละเอียดตอนเล่น** ตั้ง `SOUND_DEBUG = True` ใน `config.py`
จะพิมพ์ทุกครั้งที่เล่นไม่สำเร็จพร้อมสาเหตุ

**เช็คเองได้ทุกเมื่อ**

```python
from audio import sfx
print(sfx.diagnose())
```

### แปลง mp3 ที่มีอยู่ให้เป็น wav

repo มี `sound_effect/*.mp3` อยู่แล้ว แปลงด้วยอะไรก็ได้ — Audacity, เว็บแปลงไฟล์
หรือ ffmpeg:


## 7. กติกา

**ผลไม้** → +100 คะแนน (×2 ถ้า FEAST), ตัวยาวขึ้น 1 ท่อน, หลอด power เพิ่ม
2P มีผลไม้ 2 ลูกในสนาม และวางห่างกันอย่างน้อย 40 px

**ชนกำแพงนอก / กล่อง** → สตัน 30 เฟรม, ทิศรีเซ็ตเป็นหยุด, ตำแหน่งไม่ถูกยืนยัน (ไม่เสียเลือด)
PHASE ทะลุกล่องได้ แต่**กำแพงนอกหยุดทุกกรณี**

**ชนลำตัวตัวเอง** → **สตัน 30 เฟรม + เสียเลือด 1 ดวง** (ข้าม 2 ท่อนหลังหัว)
**ไม่เสียแต้ม** — พลาดเองเสียแค่หัวใจ

มี 3 เงื่อนไขกันเลือดไหลรัว ทั้ง 3 ข้อจำเป็น:

1. **ช่วงกัน 70 เฟรม** — ถ้าไม่มี จะตรวจซ้ำทุกเฟรมเพราะหัวยังทับลำตัวอยู่
2. **ตรวจเฉพาะเฟรมที่หัวขยับจริง** — งูที่ชนกำแพงตอนขดตัวจะ `direction='stop'`
   หัวไม่เคยออกจากลำตัวตัวเอง ถ้าไม่มีข้อนี้จะเสียเลือดทุก 70 เฟรมจนตายทั้งที่ค้างอยู่
3. **เคารพ immunity 60 เฟรม** — เพิ่งโดนศัตรูตีแล้วมาชนตัวเองซ้ำ ไม่นับ

งูไถลออกจากขดตัวเองได้เองโดยไม่ต้องกดปุ่ม · ตั้ง `SELF_HIT_DAMAGE = 0` ใน `config.py`
ถ้าอยากกลับไปเป็นสตันเฉยๆ ไม่เสียเลือด

### core game — กัดคนอื่นคือคนกัดเสียเอง

หัวใจของเกมคือ **กินผลไม้ → รักษาแต้ม → ล่อให้อีกฝั่งมากัดตัวเรา**
เพราะการกัดลงโทษ**คนกัด** ไม่ใช่คนถูกกัด งูที่แต้มเยอะจึงต้องสะบัดลำตัวและหางไปวางหน้าปากอีกฝั่งเสมอ
ส่วนงูที่แต้มน้อยต้องอดใจไม่งับเหยื่อที่ยื่นมาให้ — แต่ถ้าอดใจไว้ได้และไปเจอกันแบบหัวต่อหัว
ฝ่ายแต้มน้อยจะเป็นคนได้แต้มไปฟรีๆ นั่นคือทางทำแต้มอีกทางนอกจากกินผลไม้

**กฎข้อเดียวที่ต้องจำ: แต้มย้ายที่ได้ตอน "หัวชนหัว" เท่านั้น** การชนแบบอื่นทั้งหมด
เสียแค่ HP ไม่มีการยุ่งกับแต้มเลย

| เหตุการณ์ | ผล |
|---|---|
| **หัวชนหัว** แต้มไม่เท่ากัน | **ฝ่ายแต้มมากกว่า** เสีย −1 HP และ**โอนแต้มครึ่งหนึ่งของตัวเอง**ให้ฝ่ายแต้มน้อย · **ฝ่ายแต้มน้อยชนะ: ได้แต้มมาฟรี และไม่เสีย HP** |
| **หัวชนหัว** แต้มเท่ากันพอดี | ทั้งคู่เสีย −1 HP · **ไม่มีการโอนแต้ม** |
| **หัวเราไปโดนลำตัวหรือหางของอีกฝั่ง** (กัด) | **คนกัดเสีย −1 HP เท่านั้น** ไม่เสียแต้ม **แม้จะเป็นฝ่ายที่แต้มน้อยกว่าก็ตาม** · คนถูกกัดไม่เสียอะไร และไม่ได้อะไร |
| **ชนลำตัวตัวเอง** | −1 HP เท่านั้น ไม่เสียแต้ม |
| **ชนกำแพงนอก / กล่อง** | สตัน 30 เฟรมเท่านั้น ไม่เสีย HP ไม่เสียแต้ม |

ลำตัวกับหางถือว่า**เหมือนกัน** โดยเจตนา (กฎเก่าให้รางวัลกับการงับหาง ซึ่งขัดกับ core game)

> **หนึ่งการชน = ตัดสินครั้งเดียว** — ตอนหัวชนหัว หลังโอนแต้มแล้ว "ใครแต้มเยอะกว่า"
> จะสลับข้างทันที ถ้าไม่ล็อกไว้ เฟรมถัดไป (หัวยังติดกัน คนแพ้ยังสตันอยู่กับที่)
> จะไปลงโทษ**คนที่เพิ่งชนะการชน**แทน เกมจึงข้ามการตรวจหัวชนหัวตราบใดที่ยังมีใคร
> อยู่ในช่วง immunity — ต้องหายดีทั้งคู่ก่อน จึงนับเป็นการชนครั้งใหม่

หลังเสียเลือดมี immunity 60 เฟรม (sprite กะพริบ) กันโดนรัวๆ · SHIELD กัน HP ได้
และเพราะการโอนแต้มผูกกับการเสีย HP **SHIELD จึงกันการเสียแต้มไปด้วยโดยปริยาย**

### ชนะรอบ และ ชนะแมตช์

**ชนะ 1 รอบ** → HP ศัตรูเหลือ 0 **หรือ** ทำคะแนนถึง 500 · ถึงพร้อมกันดูคะแนนสูงกว่า · เท่ากันเป็น DRAW

**สกอร์รอบ** แสดงกลางจอตลอดเวลาเป็น `P1  1 - 0  P2` ทั้งบน HUD ตอนเล่นและบนหน้าผล
ใครถึง `ROUNDS_TO_WIN` (ค่าเริ่มต้น 2 = แข่ง 3 เอา 2) ก่อน จะจบแมตช์

**แต้มรีเซ็ตทุกรอบ** (เริ่มรอบใหม่ที่ 0 ทั้งคู่) แต่เกมจดไว้ทุกรอบ
เพื่อรวมให้ดูตอนจบแมตช์

### MVP = แต้ม × ชีวิตที่รอด

จบทุกรอบ เกมจะจดไว้ 2 อย่างต่อคน: **แต้มที่ได้ในรอบนั้น** และ **HP ที่เหลือตอนจบรอบ**
แล้วคูณกัน:

```
MVP ของรอบนั้น = แต้มในรอบ × HP ที่เหลือ
MVP รวม        = บวกทุกรอบในแมตช์
```

จุดสำคัญคือ **รอบที่ถูกน็อค (HP = 0) MVP เป็น 0** ไม่ว่าจะเก็บแต้มไว้เยอะแค่ไหน
เพราะ `แต้ม × 0 = 0` — เก็บแต้มได้ 500 แต่ตายก่อน = ได้ 0 เท่ากับไม่ได้เล่น
ดังนั้น "รอดให้ได้" มีน้ำหนักเท่ากับ "เก็บแต้มให้ได้"

| รอบ | แต้ม | HP เหลือ | MVP |
|---|---|---|---|
| R1 | 400 | 3 | **1200** |
| R2 | 150 | 0 (ถูกน็อค) | **0** |
| R3 | 300 | 0 (ถูกน็อค) | **0** |
| รวม | 850 | | **1200** |

### MVP ใช้ตอนไหน — ตัวตัดสินเสมอ

**ลำดับการตัดสินแมตช์:**

1. **จำนวนรอบที่ชนะ** — ใครมากกว่าชนะ (เช่น 2-1) · MVP ไม่มีผลเลยในกรณีนี้
2. **รอบเท่ากัน** → ดู **MVP รวม** ใครมากกว่าชนะ
3. **MVP เท่ากันอีก** → `A DRAWN MATCH` เสมอทั้งแมตช์

รอบจะเท่ากันได้เมื่อครบ `MAX_ROUNDS` (= `ROUNDS_TO_WIN × 2 - 1` = 3 รอบ) แล้วยังไม่มีใคร
ถึง 2 รอบ เช่น ชนะคนละรอบ + เสมอ 1 รอบ (1 - 1) หรือเสมอทั้ง 3 รอบ (0 - 0)

> `MAX_ROUNDS` ยังกันบั๊กด้วย: ถ้าไม่มีเพดานนี้ แมตช์ที่เสมอทุกรอบจะเล่นวนไม่จบ
> เพราะไม่มีใครถึง `ROUNDS_TO_WIN` เลย

### หน้าผลมี 2 แบบ

**1. ROUND OVER** — จบรอบย่อย แมตช์ยังไม่จบ

```
              ROUND 2 OVER
          P2 EMBER WINS THE ROUND

              P1  1 - 1  P2

           score x hp left = MVP
     P1  150 x 0 = 0      480 x 2 = 960  P2
        MVP so far    P1 1200    |    P2 960
          first to 2 rounds takes the match
       Press R for round 3     |     M for Menu
```

(`MVP so far` โชว์ตั้งแต่รอบ 2 ขึ้นไป รอบแรกไม่โชว์เพราะซ้ำกับบรรทัดบน)

**2. MATCH RESULT** — จบแมตช์ สรุปทั้งแมตช์

```
                    MATCH RESULT
                P1 AQUA WINS THE MATCH

                   P1  1 - 1  P2

  ROUND   P1  score x hp = MVP   P2  score x hp = MVP   WON BY
  R1              400 x 3 = 1200          200 x 0 = 0     AQUA
  R2                150 x 0 = 0        480 x 2 = 960    EMBER
  R3                300 x 0 = 0          300 x 0 = 0      DRAW
  ---------------------------------------------------------------
  MVP TOTAL              1200                   960    MVP: P1

           raw points   P1 850   |   P2 980
       rounds level 1 - 1  ->  MVP decides the match
          Press R for a NEW MATCH  |  M for Menu
```

อ่านได้ครบในจอเดียว: **ใครชนะแมตช์** · **แต้ม × HP ของทุกรอบ แสดงการคูณให้เห็น** ·
**MVP รวม** · **แต้มดิบรวม** (`raw points`) · และบรรทัดล่างบอกว่าตัดสินด้วยอะไร

> ตัวอย่างข้างบนคือกรณีที่ MVP ทำงาน: รอบเท่ากัน 1-1 และ P2 แต้มดิบเยอะกว่า (980 vs 850)
> แต่ P2 รอดแค่รอบเดียว MVP จึงได้ 960 ส่วน P1 รอดรอบที่เก็บแต้มเยอะ ได้ 1200 → **P1 ชนะ**
> นี่คือเหตุผลที่กติกานี้เข้ากับ core game: เก็บแต้มเก่งอย่างเดียวไม่พอ ต้องรอดด้วย

| กด R ตอนไหน | ผล |
|---|---|
| หน้า ROUND OVER | เล่นรอบต่อไป **สกอร์รอบและตาราง MVP ยังอยู่** |
| หน้า MATCH RESULT | เริ่มแมตช์ใหม่ที่ `0 - 0` ตารางเคลียร์ |
| ระหว่างเล่น | ไม่ทำอะไร (กันกดพลาด) |

กด `M` กลับเมนู = ทิ้งแมตช์นั้นทั้งหมด กลับมาเล่นใหม่คือแมตช์ใหม่
· DRAW ไม่นับรอบให้ใคร แต่ยังถูกบันทึกในตาราง (คอลัมน์ WON BY = `DRAW`)

## 8. ปรับบาลานซ์

แก้ที่ไฟล์เดียวตามหมวด:

| อยากแก้ | ไฟล์ | หัวข้อ |
|---|---|---|
| ฟอนต์ · ไอคอนหน้าต่าง · ขนาดจอ | `config.py` | Section 3A |
| **สีทุกสีในเกม** (พื้น กำแพง กล่อง ตัวหนังสือ การ์ด ปุ่ม) | `config.py` | **Section 3A2 THEME** |
| ขนาดสนาม ความเร็ว HP คะแนน เวลาสตัน กล่อง เสียง | `config.py` | Section 3B-3E |
| ตัวละคร: สี + palette ของ sprite | `config.py` | Section 3F |
| power: ผล ค่าใช้ ระยะเวลา ไอคอน คำอธิบาย | `config.py` | Section 3G |
| ตำแหน่ง HUD / หัวใจ / หลอด เฉพาะโหมด | `solo.py` / `battle.py` | Section 3 |
| จุดเกิดของงู | `battle.py` | `SPAWN` ใน Section 3 |

**ค่าที่มักอยากแก้**

```python
SCORE_TRANSFER      = 0.5   # สัดส่วนแต้มที่โอนตอนหัวชนหัว (0 = ไม่โอน, 1.0 = โอนหมด)
                            # นี่คือที่เดียวในเกมที่แต้มย้ายที่
ROUNDS_TO_WIN       = 2     # ชนะกี่รอบถึงได้แมตช์ (2 = แข่ง 3 เอา 2)
MAX_ROUNDS          = ROUNDS_TO_WIN * 2 - 1   # เพดานจำนวนรอบ คำนวณเอง ไม่ต้องแก้
TARGET_SCORE        = 500   # แต้มที่ทำถึงแล้วชนะรอบทันที
MAX_HP              = 3
SELF_HIT_DAMAGE     = 1     # เลือดที่เสียตอนชนตัวเอง (0 = สตันเฉยๆ)
WALL_MARGIN         = 10    # กันหัวจมกำแพง = ครึ่งหนึ่งของขนาด sprite
SLOT_COLOR          = {'P1': 'mediumseagreen', 'P2': 'steelblue'}
```

**อยากปรับความดุของ core game**

| อยากได้ | แก้ |
|---|---|
| ชนหัวแล้วเจ็บกว่านี้ | `SCORE_TRANSFER` เพิ่ม (1.0 = โอนแต้มทั้งหมด) |
| ไม่ให้แต้มย้ายที่เลย | `SCORE_TRANSFER = 0.0` (เหลือแค่เสีย HP) |
| ให้การกัดเสียแต้มด้วย | ใน `battle.py` `resolve_bite()` เพิ่มการหักแต้มหลัง `punish(biter)` |
| แข่ง 5 เอา 3 | `ROUNDS_TO_WIN = 3` (`MAX_ROUNDS` เป็น 5 เอง) |
| ให้ MVP ไม่สนใจ HP (กลับไปดูแต้มดิบ) | แก้ `mvp_total()` ใน `screens.py` เป็น `sum(r[slot] for r in rounds)` |
| ให้ MVP ตัดสินทุกครั้ง ไม่ใช่แค่ตอนเสมอ | ใน `match_champion()` เอาเงื่อนไขจำนวนรอบออก เหลือเทียบ MVP อย่างเดียว |
| จบรอบเร็วขึ้น | `TARGET_SCORE` ลด หรือ `MAX_HP` ลด |

ค่าคงที่ไม่ถูกประกาศซ้ำในไฟล์โหมดอีกแล้ว — แก้ที่ `config.py` ที่เดียวมีผลทั้งสองโหมด

**กฎที่ต้องรู้ (เป็นข้อจำกัดของ turtle ไม่ใช่ของเกม)**

- ต้องเป็น **GIF** — วาง `.png` ก็ได้ `load_shape()` จะแปลงเป็น `.gif` ให้ครั้งเดียว (ต้องมี Pillow)
- **turtle หมุนรูปไม่ได้** → หัวจึงต้องมี 4 ไฟล์แยกทิศ
- **turtle ย่อขยายรูปไม่ได้** → **ขนาดพิกเซลของไฟล์ = ขนาดในเกม** สั่ง `shapesize()` ไปก็ไม่มีผล
  อยากได้งูตัวใหญ่ขึ้นต้องทำไฟล์ใหญ่ขึ้น
- ความโปร่งใสของ GIF เป็นแบบ **เปิด/ปิด** ไม่มีขอบนุ่ม
- ไฟล์ไหนหายหรือเสีย เกมไม่ล้ม — จะกลับไปใช้สี่เหลี่ยมสีให้ส่วนนั้น
- ตั้ง `USE_SPRITES = False` ใน `config.py` เพื่อบังคับใช้สี่เหลี่ยมสีทั้งหมด

### 9.2 ปรับสีลำตัวเองได้ไหม — ได้ แต่ต้องไม่ใส่ body gif

**turtle ทาสีทับรูปไม่ได้** ไฟล์ `.gif` เป็น Tk image item คำสั่ง `color()` ไม่มีผลกับมันเลย
ดังนั้นถ้าใส่ `<key>_body.gif` สีลำตัวจะ**ติดมากับไฟล์** แก้จาก `config.py` ไม่ได้

หัวกับลำตัวจึงถูก**แยกการตัดสินใจออกจากกัน** เลือกได้ 4 แบบ:

| ใส่ head gif | ใส่ body gif | ผลที่ได้ |
|---|---|---|
| ✅ | ✅ | หัวและลำตัวเป็นรูปที่อัพ — สีอยู่ในไฟล์ทั้งคู่ |
| ✅ | ❌ | **หัวเป็นรูปที่อัพ ลำตัวเป็นสี่เหลี่ยมสีจาก `config.py`** ← ตอบคำถามนี้ |
| ❌ | ✅ | ลำตัวเป็นรูป หัวเป็นสี่เหลี่ยมสี |
| ❌ | ❌ | สี่เหลี่ยมสีทั้งตัว |

> **สรุป** — อยากอัพรูปหัวสวยๆ แต่ยังคุมสีลำตัวจากโค้ดได้: **อัพแค่ `<key>_head_*.gif`
> แล้วไม่ต้องมี `<key>_body.gif`** ลำตัวจะใช้ค่า `main` ของตัวละครนั้น เปลี่ยนสีที่
> `config.py` ได้ทันทีโดยไม่ต้องแตะไฟล์รูป

ทดสอบทั้ง 4 แบบแล้วว่าเรนเดอร์ออกจริงและไม่ error

> เกร็ด: `<key>_body_ghost.gif` **ยังไม่ถูกใช้เลย** เพราะตอน CLOAK เกมซ่อนลำตัวทั้งหมด
> ไม่ได้เปลี่ยนเป็นลำตัวเงา — ไม่ต้องเสียเวลาทำไฟล์นี้ (เว้นแต่จะแก้ให้ CLOAK โชว์ลำตัวเงาแทน)

## 9.4 เปลี่ยนฟอนต์

`config.py` → `FONT_CANDIDATES` เป็น **ลิสต์** ไม่ใช่ชื่อเดียว เพราะ tkinter จะเงียบๆ
สลับฟอนต์ให้เองถ้าไม่มีตัวที่ขอ ทำให้ไม่รู้ว่าได้อะไรมาจริง `engine.py` จึงถาม Tk ว่ามีฟอนต์อะไร
แล้วเลือก **ตัวแรกในลิสต์ที่เครื่องนั้นมีจริง**

```python
FONT_CANDIDATES = ['Consolas', 'Cascadia Mono', 'Courier New',
                   'DejaVu Sans Mono', 'Liberation Mono', 'Courier']
```

เอาฟอนต์ที่อยากได้ไว้หน้าสุด และเก็บ monospace กลางๆ ไว้ท้ายสุดเป็นตัวสำรอง
ลิสต์เดียวใช้ได้ทั้ง Windows และ Linux (บน Windows จะได้ Consolas บน Linux ได้ DejaVu)

## 9.5 เปลี่ยนไอคอนหน้าต่าง (แทนขนนกของ tkinter)

เอาโลโก้ไปวางใน `assets/` ตั้งชื่อตามนี้ **เอาไฟล์แรกที่เจอ**

```python
WINDOW_ICON = ['icon.png', 'icon.gif', 'logo.png', 'logo.gif', 'icon.ico']
```

| นามสกุล | ใช้ได้ที่ไหน | หมายเหตุ |
|---|---|---|
| `.png` `.gif` | **ทุก OS** (Tk 8.6+) | แนะนำ ผ่าน `iconphoto` |
| `.ico` | **Windows เท่านั้น** | ผ่าน `iconbitmap` — Linux/Tk ปฏิเสธไฟล์นี้ |

ขนาดที่เหมาะคือ 32×32 หรือ 64×64 · ถ้าไม่มีไฟล์เลยก็ใช้ไอคอนเดิมของ tkinter ต่อไป ไม่ error

## 10. หมายเหตุเชิงเทคนิค (turtle มีกับดักเยอะ)

สิ่งที่เคยทำให้เจ็บตัวมาแล้ว เก็บไว้กันพลาดซ้ำ:

- **shape หมุน 90°** — turtle หมุน shape ตาม `heading - 90` เพราะ built-in shape เขียนแบบหัวชี้ขึ้น
  shape ใน `engine.py` เขียนแบบพิกัดจอ จึงต้องแสดงผ่าน `engine.shape_turtle()` ที่ตั้ง heading 90 ให้
- **shape turtle ทับตัวหนังสือเสมอ** — turtle เรียก `tag_raise` ทุกเฟรม อะไรที่ต้องมีข้อความทับ
  ให้วาดด้วยปากกา (`engine.filled_rect`) แล้วรับคลิกด้วย `wn.onscreenclick` + `engine.inside_rect`
- **`onclick()` ใช้กับ compound shape หลายชิ้นไม่ได้** — `turtle.turtle._item` เป็น list
  `tag_bind` จึงไม่ match ให้ hit-test พิกัดเองแทน
- **ต้องล้าง turtle ตอนเปลี่ยนซีน** — `hideturtle()` ไม่พอ ต้องลบ canvas item (`items`,
  `drawingLineItem`, `_fillitem`, และ cursor ที่เป็น list ถ้าเป็น compound) แล้วถอดออกจาก
  `wn._turtles` ด้วย ไม่งั้นรั่วสะสมทุกครั้งที่สลับซีน — `engine.clear_all_turtles()` ทำให้แล้ว
- **image shape เป็น GIF เท่านั้น** และหมุน/ย่อขยายไม่ได้ → หัวงูต้องมี 4 ไฟล์ต่อทิศ
  และ **ทาสีทับไม่ได้** (`color()` ไม่มีผลกับ Tk image item) สีจึงติดมากับไฟล์ — ดูข้อ 9.2
- **การวางท่อนลำตัว** เดินย้อน path สะสมระยะทาง ไม่ใช่นับเฟรม ไม่งั้นตอน SPEED ลำตัวจะยืดห่าง
- **sprite วาดจากจุดกลาง** ถ้าปล่อยให้ *จุดกลาง* ของหัวไปถึงขอบสนามได้ ครึ่งหนึ่งของ sprite
  จะจมเข้าไปในกำแพง (วัดได้ 10 px พอดี = ครึ่งของหัว 20×20) จึงต้องหักขอบด้วย `WALL_MARGIN`
- **tkinter สลับฟอนต์ให้เองแบบเงียบๆ** ถ้าไม่มีตัวที่ขอ ต้องถาม `tkinter.font.families()`
  ว่ามีอะไรจริงก่อนเลือก — `engine._pick_font()` ทำให้แล้ว
