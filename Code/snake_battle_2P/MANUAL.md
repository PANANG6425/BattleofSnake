# Snake Battle — Local Multiplayer | MANUAL

> Language: **ไทย** · [English](MANUAL.en.md) · [日本語](MANUAL.ja.md)

เกมงูต่อสู้ 2 คนบนเครื่องเดียว เขียนด้วย `turtle` ล้วน (ไม่ใช้ pygame)
ต่อยอดจาก `snake_baseline1P.py`

> **เวอร์ชันนี้แยกไฟล์เป็นโมดูลแล้ว** — จุดเริ่มคือ `main.py` (ไฟล์เดียว `snake_battle_2P.py` เดิมเลิกใช้)

---

## 1. ติดตั้ง & รัน

**ต้องมี**

- Python 3.8+ ที่มี `tkinter` (turtle ใช้ tkinter ข้างใน)
  - Windows / macOS: installer ของ python.org มีมาให้แล้ว
  - Ubuntu / Debian: `sudo apt install python3-tk`
- **ไม่ต้องลงอะไรเพิ่มเพื่อเล่น** — เสียงกับรูปที่แถมมาใช้ได้เลย
- ของเสริม (เฉพาะตอนจะ generate ใหม่ / อยากได้เสียงคุณภาพดีกว่า)
  - `pip install pillow` — เฉพาะตอนรัน `make_sprites.py` หรือจะวางรูป `.png` เอง
  - `pip install pygame` — ถ้าลง เสียงจะเล่นทับกันได้และดีเลย์ต่ำที่สุด (ไม่ลงก็มีเสียง)

**รัน**

```bash
python main.py            # เล่นเกม
python make_sprites.py    # สร้างรูป GIF ใหม่ทั้งชุด (ต้องมี Pillow)
python make_sounds.py     # สร้างเสียง WAV ใหม่ทั้งชุด (ใช้ stdlib ไม่ต้องลงอะไร)
```

**โครงไฟล์**

```
snake_battle_2P/
├── main.py          ← จุดเริ่ม รันไฟล์นี้ (ประกอบทุกโมดูล + game loop + หน้า Result)
├── config.py          ค่าคงที่ทั้งหมด ปรับบาลานซ์ที่นี่
├── screen.py          สร้างหน้าต่าง turtle ตัวเดียวของเกม (Screen เป็น singleton)
├── sprites.py         โหลด GIF เข้า turtle + แปลง PNG→GIF ให้
├── sounds.py          เล่นเสียงแบบไม่บล็อก เลือก backend อัตโนมัติ
├── effects.py         particle system (ฝุ่น/ประกาย)
├── arena.py           กำแพง + กล่องอุปสรรค + เช็คชนกล่อง
├── snake.py           คลาส Snake (สร้าง 2 ตัว = multiplayer)
├── fruit.py           ผลไม้ + สุ่มตำแหน่งที่ปลอดภัย
├── hud.py             แถบ stats ด้านบน + หลอด stun เหนือหัวงู
├── rules.py           กติกาต่อสู้ / กินผลไม้ / เงื่อนไขชนะ
├── make_sprites.py    generator รูป (ของเสริม)
├── make_sounds.py     generator เสียง (ของเสริม)
└── assets/
    ├── *.gif          รูป sprite
    └── sounds/*.wav   เสียง
```

ลำดับ import: `config` → `screen` → `sprites`/`sounds` → `arena`/`effects` → `snake`/`fruit` → `rules`/`hud` → `main`
**ห้ามให้โมดูลล่างย้อนไป import โมดูลบน** (จะเกิด circular import)

> ถ้า `assets/` หายหรือไฟล์เสีย เกม**ยังรันได้** — รูปกลับไปเป็นสี่เหลี่ยมสี เสียงเงียบ

## 3. กติกา

### เก็บของ / ชนสิ่งกีดขวาง

| เหตุการณ์ | ผล |
|---|---|
| กินผลไม้ 🍎 | +100 คะแนน, ยาวขึ้น 1 ข้อ, skill bar +25, เสียง `eat` + ประกาย |
| ชนกล่องอุปสรรค | สตัน 30 เฟรม + ฝุ่น + เสียง `bump` — **ไม่ตาย ไม่เสีย HP** |
| ชนกำแพงรอบสนาม | เหมือนกล่องอุปสรรค |
| กินตัวเอง/หางตัวเอง | สตัน — **ไม่ตาย** และงูจะวิ่งออกจากตัวเองได้เอง (ดูข้อ 9) |

### การโจมตี — กฎเดียวกันทั้งสองฝ่าย

| หัวเราไปชน | ผล |
|---|---|
| **หัว** ศัตรู | ศัตรูเสีย 1 HP + คะแนนศัตรู −50% |
| **หาง** ศัตรู (ข้อสุดท้าย) | ศัตรูเสีย 1 HP + คะแนนศัตรู −50% |
| **ลำตัว** ศัตรู (ข้อกลาง) | **เราเสียเอง** 1 HP + คะแนนเรา −50% |

- ชนหัวใส่หัวพร้อมกัน = เสียทั้งคู่ (กฎถูกเช็คทั้งสองทิศทาง)
- หลังโดนตี **immunity 60 เฟรม** sprite จะกระพริบ ช่วงนี้โดนซ้ำไม่ได้
- ระยะนับว่าชน 12 px (ชนตัวเอง 10 px)

### สกิล (จ่าย 50 bar, อยู่ 180 เฟรม ≈ 3 วิ)

| สกิล | ผล |
|---|---|
| Speed Boost | 3 → 6 px/เฟรม |
| Invisibility | ลำตัวหาย หัวเป็นรูปจางๆ — **ยังชนได้ปกติ** |

### เงื่อนไขชนะ

1. ศัตรู HP = 0 → ชนะ
2. คะแนนถึง 500 → ชนะทันที
3. ถึงพร้อมกัน → คะแนนสูงกว่าชนะ / เท่ากัน = DRAW
4. HP หมดพร้อมกัน = DRAW

## 4. ปรับบาลานซ์ — แก้ที่ `config.py` ที่เดียว

| ตัวแปร | ค่าเริ่ม | ความหมาย |
|---|---|---|
| `MAX_HP` | 3 | หัวใจต่อคน (ไอคอนหัวใจปรับจำนวนตามเอง) |
| `TARGET_SCORE` | 500 | คะแนนที่ชนะทันที |
| `FRUIT_SCORE` / `FRUIT_COUNT` | 100 / 2 | คะแนนต่อผล / จำนวนผลไม้ในสนาม |
| `SCORE_PENALTY` | 0.5 | ตัวคูณคะแนนเมื่อโดนตี |
| `BASE_SPEED` / `BOOST_SPEED` | 3 / 6 | px ต่อเฟรม ปกติ / Boost |
| `SEG_SPACING` | 15 | ระยะห่างข้อลำตัว |
| `START_LENGTH` | 4 | ความยาวเริ่มต้น |
| `SKILL_COST` / `SKILL_GAIN` / `SKILL_FRAMES` | 50 / 25 / 180 | ค่าใช้ / ที่ได้ต่อผล / ระยะเวลา |
| `STUN_FRAMES` | 30 | สตันกี่เฟรม |
| `INVULN_FRAMES` | 60 | immunity หลังโดนตี |
| `BUMP_COOLDOWN` / `SELF_HIT_COOLDOWN` | 45 / 45 | กันสตันซ้ำรัวๆ — **ต้องมากกว่า `STUN_FRAMES`** |
| `HIT_RADIUS` / `SELF_HIT_RADIUS` | 12 / 10 | ระยะนับว่าชน |
| `SELF_SKIP_SEGMENTS` | 3 | ข้อหลังหัวที่กัดตัวเองไม่ได้ |
| `OBSTACLE_COUNT` / `OBSTACLE_SIZE` / `OBSTACLE_SPOTS` | 6 / 60 / list | กล่องอุปสรรค |
| `FRAME_MS` | 16 | ms ต่อเฟรม (16 ≈ 60 FPS) |
| `PLAYER_SETUP` | — | ชื่อ/สี/จุดเกิดของผู้เล่น |
| `FX_*` | — | จำนวน/อายุ particle |
| `SOUND_ON` / `SOUND_VOLUME` | True / 0.6 | เสียง |
| `USE_SPRITES` | True | `False` = บังคับใช้สี่เหลี่ยมสีแบบเดิม |

> **ระวัง 2 อย่าง**
> 1. `BUMP_COOLDOWN` และ `SELF_HIT_COOLDOWN` **ต้องมากกว่า** `STUN_FRAMES` — ช่องว่างนี้คือสิ่งที่รับประกันว่างูวิ่งออกจากที่ค้างได้ ถ้าตั้งให้น้อยกว่า บัค deadlock จะกลับมา
> 2. `BOOST_SPEED` ไม่ควรเกิน ~`SEG_SPACING` — เร็วกว่านั้นหัวจะ "กระโดด" ข้ามกล่อง/ตัวศัตรูในเฟรมเดียว เพราะเช็คชนเป็นจุดต่อจุด ไม่ได้เช็คเส้นทางระหว่างเฟรม

## 5. ลำดับการทำงานใน 1 เฟรม (`main.game_loop`)

```
1. tick_timers()        ลดเวลา stun / immunity / cooldown / สกิล แล้วตั้งความเร็ว
   move()               ขยับหัว (ถ้าชน = ไม่ commit ตำแหน่ง)
   refresh_segments()   คำนวณตำแหน่งข้อลำตัว "ครั้งเดียว" ต่อเฟรม แล้ว cache ไว้
2. resolve_fruit()      กินผลไม้
   resolve_self_collision()
3. resolve_attacks(p1→p2) แล้ว resolve_attacks(p2→p1)
4. render()             วาดลำตัว แล้ว stamp หัวทับ
   effects.update_and_draw()   particle
   hud.draw_panel()            แถบ stats
   hud.draw_stun_bars()        หลอด stun เหนือหัว (วาดท้ายสุด = อยู่ชั้นบนสุด)
5. check_win()          ถ้ามีผู้ชนะ → show_result() แล้วหยุด loop
   wn.update()          ดันภาพขึ้นจอทีเดียว
   ontimer(16 ms)       นัดเฟรมถัดไป
```

## 6. กลไกที่ควรอธิบายได้ (จุดที่ไม่ตรงไปตรงมา)

1. **ลำตัวมาจาก path history ไม่ใช่ list ของ turtle**
   `move()` เก็บพิกัดหัวทุกเฟรมลง `self.path` แล้ว `_compute_segments()` เดินย้อนกลับ **นับระยะทางสะสม** ทุก 15 px วาง 1 ข้อ
   *ทำไมนับระยะไม่นับเฟรม:* ตอน Boost เดิน 6 px/เฟรม ถ้านับเฟรมข้อจะห่างเป็น 2 เท่า ลำตัวยืด

2. **`refresh_segments()` เรียกครั้งเดียวต่อเฟรม**
   เดิม `segments()` ถูกคำนวณซ้ำ 3–4 รอบต่อเฟรมต่อคน (rules เรียก 3 ที่ + render) ตอนนี้ cache ไว้ตัวเดียว

3. **หัวถูก stamp เป็นอันสุดท้าย**
   canvas ของ turtle ทับกันตามลำดับที่สร้าง ถ้าหัวเป็น turtle ที่สร้างตอน `__init__` ลำตัวที่ stamp ทีหลังจะทับหัว → เลยซ่อน turtle หัวไว้เป็นแค่ตัวอ้างอิงตำแหน่ง/การชน แล้ววาดหัวด้วย stamp ตอนท้าย

4. **ทั้งลำตัวใช้ turtle แค่ตัวเดียว** (`clearstamps()` + `stamp()`) งูยาวขึ้นไม่ต้องสร้าง object เพิ่ม

5. **`path` ถูกตัดทุกเฟรม** เก็บเท่าที่ต้องใช้ ไม่งั้น list โตไม่หยุด

6. **แถบ stats มีพื้นที่ของตัวเอง** `ARENA_T = 205` และกำแพงบนวาดที่ y=210 → งู/ผลไม้ทับตัวเลขไม่ได้

7. **cooldown คือสิ่งที่กัน deadlock** (ดูข้อ 9)

## 7. ข้อจำกัดของ turtle & เสียง

### turtle

| ข้อจำกัด | ผลต่อโค้ด |
|---|---|
| image shape รับแค่ **GIF** | `sprites.py` แปลง PNG→GIF ให้ด้วย Pillow |
| **หมุนรูปไม่ได้** | ต้องมีหัวแยก 4 ทิศ แล้วสลับ `shape()` ตาม `facing` |
| **`shapesize()` ไม่มีผลกับรูป** | ขนาดพิกเซลของไฟล์ = ขนาดในเกม |
| **`color()` ไม่มีผลกับรูป** | เอฟเฟกต์ต้องสลับรูป (ghost) หรือกระพริบ (ไม่ stamp) |
| ชื่อ shape = **path ที่ส่งเข้า `addshape()`** | โค้ดเก็บ path เป็นชื่อ shape ตรงๆ |
| GIF transparency **ทึบ/ใสเท่านั้น** | ขอบแข็งเล็กน้อย เป็นเรื่องปกติ |
| `Screen` เป็น **singleton** | มีแค่ `screen.py` ที่เรียก `turtle.Screen()` |
| `tracer(0)` | ต้องเรียก `wn.update()` เองทุกเฟรม |

### เสียง

`sounds.py` ไล่หา backend ตามลำดับ ตัวไหนใช้ได้ก่อนชนะ:

1. **pygame.mixer** — ดีสุด เล่นทับกันได้ ปรับ volume ได้ (ต้อง `pip install pygame`)
2. **winsound** — Windows, มากับ Python, เล่นได้ทีละเสียง
3. **command line** — `afplay` (macOS) / `paplay`, `aplay`, `ffplay` (Linux)
4. **silent** — ไม่มีอะไรใช้ได้ → `play()` ไม่ทำอะไร เกมยังเล่นได้ปกติ

ทุก `play()` ห่อ try/except ไว้ — ไฟล์เสียงหายหรือการ์ดเสียงมีปัญหา **ห้ามทำให้เกมพัง**
แถบล่างกลางจอบอกสถานะเสียง (`SOUND: on` / `off` / `none`) กด `M` สลับได้
ส่วนชื่อ backend ที่เลือกได้จะ print ออก terminal ตอนเปิดเกม

## 8. เปลี่ยนรูป / เปลี่ยนเสียงเป็นของทีม

วางไฟล์ทับใน `assets/` **ชื่อเดิม ขนาดเดิม** ไม่ต้องแก้โค้ด

| ไฟล์ | ขนาด |
|---|---|
| `p1_head_{up,down,left,right}.gif` | 20×20 |
| `p1_head_{...}_ghost.gif` | 20×20 |
| `p1_body.gif`, `p1_body_ghost.gif` | 16×16 |
| (ชุดเดียวกันของ `p2_`) | |
| `heart_full.gif`, `heart_empty.gif` | 18×18 |
| `fruit.gif` | 16×16 |
| `sounds/{eat,hit,bump,skill,win}.wav` | — |

- วางเป็น `.png` ก็ได้ (ชื่อเดียวกัน) รันครั้งแรกจะแปลงเป็น `.gif` ให้ (ต้องมี Pillow)
- วาดหัวให้ **หันขวา** เป็นต้นแบบ แล้วให้ `make_sprites.py` หมุนครบ 4 ทิศ
- ถ้าเปลี่ยนขนาดรูปให้ใหญ่ขึ้น ต้องขยับ `SEG_SPACING` และ `HIT_RADIUS` ตาม
- แก้สี/ทรงงู → `PALETTES` ใน `make_sprites.py` แล้วรันใหม่
- แก้เสียง → แก้ตัวเลขใน `make_sounds.py` แล้วรันใหม่ หรือวาง `.wav` ของตัวเองทับ
  แต่ละเสียงเป็นบรรทัดเดียว: `tone(ความถี่เริ่ม, ความถี่จบ, ความยาว_ms, wave_fn, decay, noise)`
  เช่น `save(tone(660, 880, 60) + tone(880, 1320, 70), 'eat')` = 2 โน้ตไล่ขึ้นต่อกัน
  เลือกทรงคลื่นได้ระหว่าง `square` (chiptune) กับ `saw` (สว่างกว่า) และต่อโน้ตด้วย `+` / เว้นจังหวะด้วย `silence(ms)`
- เพิ่มเสียงใหม่ → เติมชื่อใน `SOUND_NAMES` ที่ `sounds.py` แล้วเรียก `sfx.play('ชื่อนั้น')` ตรงจุดที่ต้องการ

## 9. บัคที่แก้แล้ว — deadlock ตอนกินหางตัวเอง / ชนกำแพง

**อาการเดิม:** กินหางตัวเองแล้วผู้เล่นค้าง เล่นต่อไม่ได้เลย / ชนกำแพงแล้ววนสตันไม่จบ

**ต้นเหตุจริงมี 3 อย่างที่ทำงานร่วมกัน**

1. ตอนชน โค้ดเดิมสั่ง `direction = 'stop'` → งูหยุดนิ่ง ลำตัวจึงไม่ขยับหนีออกจากหัว
2. `turn()` เดิมเช็คกับ `direction` → ตอน `direction == 'stop'` **กลับหลัง 180° ได้** ซึ่งพาหัวมุดเข้าคอตัวเอง
3. ไม่มี cooldown → ทุกครั้งที่ขยับ 3 px หัวก็ยังทับลำตัวเดิม เลยถูกสตันใหม่ทันที วนไม่จบ

**วิธีแก้**

| แก้ | ที่ไหน |
|---|---|
| **ไม่ล้าง `direction`** เมื่อชนกำแพง/กล่อง/ตัวเอง — งูวิ่งต่อและออกจากจุดที่ค้างได้เอง | `snake.move()`, `rules.resolve_self_collision()` |
| `turn()` เช็คกับ **`facing`** แทน `direction` → กลับหลัง 180° ไม่ได้ทุกกรณี ทางหนีคือเลี้ยวซ้าย/ขวา (มีให้เสมอ) | `snake.turn()` |
| `BUMP_COOLDOWN` / `SELF_HIT_COOLDOWN` = 45 (> `STUN_FRAMES` 30) → มีช่วง 15 เฟรม ≈ 45 px ที่ขยับได้โดยไม่ถูกสตันซ้ำ **การันตีว่าออกได้** | `config.py`, `snake.tick_timers()` |
| กดปุ่มค้างใส่กำแพงก็ไม่สตันรัว (cooldown กันไว้) | `snake.move()` |

ผลทดสอบ headless: โค้ดเก่าเดินได้ **0 px ใน 5 วินาที** (ค้างจริง) — โค้ดใหม่กินหางตัวเองแล้วเดินต่อได้ 360 px, ชนกำแพงแล้วเลี้ยวหนีได้ทันที, HP ไม่ลดจากการชนตัวเอง

## 10. แก้ปัญหาที่เจอบ่อย

| อาการ | สาเหตุ / วิธีแก้ |
|---|---|
| `ModuleNotFoundError: tkinter` | ติดตั้ง `python3-tk` (Linux) หรือใช้ Python จาก python.org |
| กดปุ่มแล้วงูไม่ขยับ | ยังไม่ได้คลิกหน้าต่างเกม |
| งูเป็นสี่เหลี่ยมสี ไม่ใช่รูป | `assets/` ไม่อยู่ในโฟลเดอร์เดียวกับ `main.py` → รัน `python make_sprites.py` |
| ไม่มีเสียง | ดูแถบล่างกลางจอ ถ้าขึ้น `SOUND: none` แปลว่าไม่มีไฟล์ (`python make_sounds.py`) หรือไม่มี backend (`pip install pygame`) |
| เสียงดีเลย์ / ขาด | ลง `pygame` แล้วจะดีขึ้นมาก (backend `cli` เปิด process ใหม่ทุกครั้ง) |
| `ImportError: cannot import name ...` | แก้ import ผิดลำดับ ดูกฎห้าม import ย้อนกลับในข้อ 1 |
| เกมกระตุก | ลด `FX_MAX` / `OBSTACLE_COUNT` หรือเพิ่ม `FRAME_MS` (16 → 20) |
| หน้าต่างเปิดแล้วปิดทันที | รันจาก terminal จะเห็น error จริง |
