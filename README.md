# Snake Battle — Local 2P conversion notes

Source: `snake_baseline1P.py` (TRON single-player starter) → `snake_battle_2P.py`.
Everything is still plain `turtle` + `wn.ontimer` at ~60 FPS, same section layout and
line-by-line comment style as the baseline.

Files: `snake_battle_2P.py`, `make_sprites.py`, `assets/*.gif` (assets/ must sit next
to the .py file).

## What changed from the baseline

| Baseline (1P) | Now (2P local) |
|---|---|
| One `p1` turtle with a pen trail | `Snake` class instantiated twice (`p1`, `p2`) |
| Trail = `pendown()` line | Real body segments stamped from path history (needed for head/tail/body rules) |
| Wall / trail hit = GAME OVER | Wall, obstacle and self-hit = **stun only**, no death |
| No fruit / HP / skills | Fruit, HP hearts, score, skill bar, 2 skills |
| No obstacles | 6 filled boxes drawn with a dedicated `obstacle_pen` turtle |
| Colored squares | GIF sprite snakes + heart icons + drawn skill bars |

## Controls

- **P1**: `W A S D` — `Q` = Speed Boost, `E` = Invisibility
- **P2**: Arrow keys — `O` = Speed Boost, `P` = Invisibility
- `R` = restart from the result screen

## Rules as implemented

- Fruit → +100 score, +1 body segment, +25 skill bar (2 fruits on the field, cap 100)
- Obstacle box / outer wall → stun 30 frames, direction reset to `stop`, position not committed
- Own body → stun (skips the 2 segments right behind the head)
- Attacks (symmetric, evaluated both directions each frame):
  - head → enemy **head**: enemy −1 HP, enemy score ×0.5
  - head → enemy **tail** (last segment): enemy −1 HP, enemy score ×0.5
  - head → enemy **body** (any middle segment): **attacker** −1 HP, attacker score ×0.5
- 60 immunity frames after a hit (sprite flickers) so one touch can't chain-hit
- Skills cost 50 bar, last 180 frames: Boost = 3→6 px/frame; Invisibility = body hidden,
  head swapped to a faded ghost sprite (still fully collidable — the owner needs to track
  it on a shared screen)
- Win: enemy HP 0, or reach 500 score. Both at once = higher score, tie = DRAW.

## Sprites (SECTION 2B + make_sprites.py)

turtle constraints that shaped the design:

- image shapes must be **GIF** (`wn.addshape(path)`); PNG is not accepted
- image shapes **cannot rotate or scale** → each snake ships 4 head sprites
  (`p1_head_up/down/left/right.gif`) and the code swaps shape on `self.facing`
- `shapesize()` has no effect on image shapes, so sprite pixel size *is* the game size

Sprite set (all generated by `python make_sprites.py`, Pillow required only for generating):
`{p1,p2}_head_{up,down,left,right}[_ghost].gif` (20×20), `{p1,p2}_body[_ghost].gif` (16×16),
`heart_full.gif` / `heart_empty.gif` (18×18), `fruit.gif` (16×16).

- `load_shape(name)` looks for `assets/<name>.gif`; if only `<name>.png` exists it converts
  it once via Pillow, then registers the GIF. Missing/broken files → the game falls back to
  the original colored squares, so it always runs. `USE_SPRITES = False` forces fallback.
- **Draw order matters**: the head is *stamped last* each frame (not drawn as a visible
  turtle) because turtle canvas items keep creation order — otherwise body stamps created
  later cover the head. The head turtle stays as the invisible position/collision anchor.
- GIF transparency is binary (index 255 marked transparent in `make_sprites.py`).

## Stats HUD

Own strip above the arena: `ARENA_T = 205` and the border is drawn to y=210, so snakes and
fruits can never wander behind the panel. Per player: heart icon row (`heart_icons` pool,
one reusable turtle per max HP, shape swapped full/empty), score text, and a skill bar drawn
with `bar_pen` (gray frame + `begin_fill()` bar in the player color), plus BOOST/CLOAK/STUN
tags. `PANEL` dict holds the mirrored geometry for p1/p2.

## Balance constants (all in SECTION 2)

`MAX_HP 3`, `TARGET_SCORE 500`, `FRUIT_SCORE 100`, `OBSTACLE_COUNT 6`,
`OBSTACLE_SIZE 60`, `SEG_SPACING 15`, `BASE_SPEED 3`, `BOOST_SPEED 6`.
Obstacle rows at y = 65 / −135, spawns at (±250, −35) so the spawn corridor is clear.

## Implementation details worth knowing

- Body segments are placed by **walking the path history backwards accumulating distance**,
  not by a fixed frame offset — otherwise the body spreads apart during Speed Boost.
- One stamper turtle per player (`clearstamps()` + `stamp()` each frame) instead of one
  turtle per segment, so growth costs nothing.
- `path` is trimmed each frame to `(length+2)*SEG_SPACING/BASE_SPEED + 8` entries so memory
  stays flat in a long match.
- Obstacle layout is a fixed symmetric 3×2 grid so neither player gets a better spawn;
  `obstacles` holds `(left, bottom, right, top)` bounds for collision.
